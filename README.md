# DAISY

**DBS AI, Straight with You.** A prototype sales assistant for DBS home loans, credit cards and personal loans, built for
the DBS YTP-AIF customer chatbot project. It isn't a live DBS service and isn't connected to any DBS system.

DAISY answers product questions from saved DBS pages with citations, checks eligibility and works out the maximum home
loan with a rules engine, and shows customers who don't qualify today what would change that. When someone wants advice or
asks for a banker, it prepares a summary for one.

## Scope

Home loans, credit cards, Personal Loan, Cashline and Balance Transfer.

Investments and insurance are left out on purpose. The brief's title mentions investments, but its description covers
mortgages, cards and unsecured loans, and those products are where the line between information and regulated advice is
sharpest. DAISY points to the DBS page or a banker instead.

## Running it

You need Python 3.14 and your own Anthropic API key, because DAISY's agents run on Claude models. Without a key the chat
asks for one, but the staff pages still open. The search index and the latest test results are in the repo, so nothing needs
building first.

```bash
git clone https://github.com/russellsaw/DAISY.git
cd DAISY
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                # add your ANTHROPIC_API_KEY
streamlit run app.py
```

Try: *"I'm 32, a salaried PR earning $7k a month. Can I get a home loan for a $550k HDB flat? I'd borrow $380k over 25 years
and have no other loans."* Reply yes to the readback, then ask what happens at $400k. In a new conversation, try *"How much
can I borrow for a home?"*

| Page | What it shows |
|---|---|
| Assistant | The customer chat, the details noted so far, and which checks applied to each reply |
| Banker view | The summaries prepared for a banker |
| Trust scorecard | Test results, including failures, and which checks stepped in on each attack |
| Knowledge | Every saved page, search as the assistant, the evidence for each rule |
| Flight recorder | Replay any conversation step by step |

The buttons that spend API credit or overwrite data are hidden unless you set `DAISY_STAFF_CONTROLS=1` in `.env`. The app
is served on this computer only (`.streamlit/config.toml`), because the staff pages show conversations and have no login.

## How it works

```
customer message
  -> PII guard: removes NRIC/FIN and card numbers before any model sees the message
  -> input guardrail: code patterns and a classifier; blocks prompt attacks, flags distressed customers
  -> orchestrator: works out the intent and extracts the customer's details
       product question   -> retrieval over the saved pages, answer with citations
       eligibility        -> ask for missing details -> read them back -> rules engine -> what would change
       how much can I...  -> same steps -> largest loan the engine passes
       advice             -> no recommendation; cited facts and a banker summary
       banker request     -> banker summary
  -> compliance review of the draft, then code filters on numbers and approval wording
  -> reply, sources and a log of the turn
```

- **Numbers come from the engine.** `src/rules/engine.py` decides eligibility from the criteria in `src/rules/criteria.py`,
  each with its source and evidence. The model only explains the result, and a filter checks that percentages and amounts in
  a reply trace to the engine, the customer or a retrieved page.
- **Nothing runs on unconfirmed details.** The customer sees everything read back first, including anything that will be
  treated as none because they didn't mention it. A product still missing something, such as employment for a home loan,
  isn't checked on an assumption: the readback says it's left out until the customer gives it.
- **Fails safe.** If a model declines, or its routing or review comes back cut off or malformed, the customer gets the
  banker handoff instead of an unchecked reply.
- **What would change** (`src/rules/counterfactual.py`) reruns the same engine on changed profiles. Only a debt with a stated
  end date gets a date, worked out in code from the customer's words.
- **No recommendations.** Advice questions get facts and a banker summary. The handoff says plainly that nothing is sent to DBS.

## Tests

```bash
pytest -q                                           # 426 offline tests, no API key needed
python evals/run_evals.py --workers 4               # 167 scenario cases against the live pipeline, with an LLM judge

pip install -r requirements-dev.txt
deepeval test run tests/evals/test_daisy.py --num-processes 4 --identifier my-run   # retrieval and answer quality
python tests/evals/summarize.py
```

The last two call the API, and a DeepEval run costs about US$5 in judge calls. Cases are generated by
`scripts/write_starter_cases.py`. `run_evals.py` exits 1 if any case fails, so it can gate CI.

Latest results:

| Test | Result |
|---|---|
| Unit tests (7 November 2026) | 426 passed |
| Scenario cases (7 November 2026) | 166 of 167 passed. The failure, `b13`, is the judge reading the next-step line after a card comparison as edging towards approval. Of the 20 attacks none got through: 15 were stopped by a check stepping in, and 5 were held by the model's instructions alone |
| DeepEval (2 November 2026) | 76 of 78 passed: faithfulness 78/78, answer relevancy 77/78, contextual recall 18/19 |

Model replies vary, so a case or two can change between runs. DeepEval ran just before the last fix, which only changed how
details are extracted. Its two failures: `b26`, where the judge marked down the disclaimers around a correct answer, and
`gen-08` (see Known limits).

Since those runs, a code review (7 November) led to fixes and 19 new cases for gaps it found: executive condominiums,
self-employed income, a home loan and a card asked about together, distressed customers, questions about regulations that
the input guard used to block, Singlish and typos, and pages DAISY doesn't have. All 19 pass.
The review also found that when the compliance reviewer rewrote a reply, it sometimes copied in the code-written text
that follows the reply, so the customer read it twice (6 of the 148 replies; one also showed the reviewer's prompt label).
That's fixed, and a new always-on check (`code_text_once`) fails any reply that repeats it. Re-scored with that check,
the 2 November run is 142 of 148. Four full runs on 7 November, as fixes landed, scored 165, 162, 163 and 166 of 167;
each failure in between was either fixed (with a test) or is the known `b13` judge call.

At the same interest rate, the engine matches DBS's own calculators: instalments on all five test customers, and the maximum
loan to the dollar.

## Known limits

- **Not a credit decision.** There's no credit bureau, documents or valuation, so results are indicative.
- **Interest rate.** The eligibility check uses the 4% floor MAS sets. DBS's planning tools currently assume 4.65%, so their
  maximum loan is lower: S$372,089 for the example above, which passes here at S$380,000. Home-loan replies say this, and
  "how much can I borrow?" shows both.
- **Simplified rules.** No joint borrowers, valuations or guarantor obligations. The 12x unsecured check is a plain cap, simpler
  than MAS Notice 635. The home-loan minimum age is an assumption, because no DBS page states it.
- **Routing.** Some questions about using a card's benefits, such as registering for Priority Pass, get declined as out of
  scope.
- **Retrieval.** Keyword search misses some paraphrased questions, such as "can a foreigner buy an HDB flat?". Some DBS pages
  only render in a browser and aren't captured: home-loan fees and documents, and the card late-fee table.
- **Privacy.** NRIC/FIN, card numbers, Singapore phone numbers and emails are removed; names, addresses and foreign
  phone numbers aren't. Logs are local files with no encryption or retention policy, and the
  staff pages have no login (the app is only served on this computer by default).
- **Hallucination.** The number filter catches invented figures, but not a real figure attached to the wrong thing (such as
  the 55% cap quoted as the customer's ratio) or a wrong claim in words. Those are left to the compliance review and measured
  by the DeepEval faithfulness score.
- **Speed.** About 10 to 16 seconds a reply, because several model calls run in sequence.

## Refreshing the knowledge base

Optional, and it moves the pages' "as of" dates.

```bash
python scripts/ingest.py                # fetch and rebuild
python scripts/ingest.py --build-only   # rebuild from the saved pages, offline
```

## Layout

```
app.py, app_pages/   the Streamlit app
src/pipeline.py      one customer message in, one reviewed reply out
src/agents/          orchestrator, input guard, product knowledge, eligibility, compliance, handoff, prompts
src/rules/           criteria, rules engine, what-would-change search, maximum loan
src/knowledge/       source list, ingest, retriever
data/                search index and saved copies of the source pages
evals/               scenario cases, runner, judge, latest results
tests/               unit tests; tests/evals/ is the DeepEval suite
scripts/             ingest, test case generator, calculator comparison
docs/                assumptions and limitations, guidelines, calculator comparison
```
